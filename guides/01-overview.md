# 课程概览与分工

本章先花几分钟搞懂三件事：**我们要做什么任务**、**为什么仿真很重要**、以及**这台机器人和服务器的分工**。后面每一章的实操都建立在理解这些概念之上。

## 任务：抓取试管，放入试管架

今天要完成的任务很简单：桌面上散落着几支**离心管（试管）**，机器人要把它们抓起来，整齐地放进旁边的**黄色试管架**里。

:::{figure} images/task-wireframe.gif
:alt: 任务示意图：桌面上的试管与目标试管架
:width: 80%

任务示意：试管散落在桌面上，机器人要把它们放进试管架。
:::

这个任务听起来简单，但真做起来并不容易：

- 机器人靠**两台 2D 相机**看世界，没有深度信息，对准试管架需要很准。
- 机器人**抓住试管后，腕部相机就会被自己的手挡住**，策略必须在「看不全」的情况下继续干活。
- 试管是圆的、会滚动，需要不断微调角度和位置。

:::{note}
SO-101 不是工业级机器人，但它是一台很适合学习的平台。你在这里学到的一整套**工作流**，之后可以直接套用到更复杂的机器人和任务上。
:::

## 为什么用仿真？

在真实机器人上试错，又慢、又贵、又危险。仿真能解决这些问题：

| 挑战 | 真实世界 | 仿真 |
|---|---|---|
| 训练速度 | 实时 1 倍速 | 可并行、大幅加速 |
| 硬件成本 | 单台数万到数十万 | 只有电费/算力成本 |
| 失败代价 | 可能损坏设备 | 按一下重置即可 |
| 场景多样性 | 手工摆 | 程序化随机生成 |

所以我们的策略是：**先在仿真里快速迭代，再搬到真实机器人上**。

## 什么是 sim-to-real 鸿沟？

「sim-to-real 鸿沟」指的是：**一个策略在仿真里很成功，到了真实机器人上却可能明显变差**。

它由四类「小鸿沟」叠加而成：

| 鸿沟类别 | 是什么 | 例子 |
|---|---|---|
| **感知鸿沟** | 仿真相机太"干净" | 真机有噪声、模糊、光照不一致、畸变 |
| **执行鸿沟** | 仿真电机太"理想" | 真机有摩擦、间隙、热效应、控制频率差异 |
| **物理鸿沟** | 仿真物理是近似 | 接触摩擦、可变形物体很难模拟准 |
| **建模鸿沟** | 模型与实物有偏差 | CAD 模型、质量、转动惯量只是估计值 |

:::{warning}
sim-to-real 鸿沟通常比你想象得更大。**不要指望仿真里跑得很好的策略，上了真机就能"直接能用"。** 一定要系统性地测试和迭代。
:::

整门课，你就是在亲身体验这条鸿沟，并学习怎么缩小它。

## 你的机器人和遥控器

SO-101 通常是**一主一从**两台臂成对出现：

- **从臂（follower / robot）**：真正执行任务的机械臂，末端带夹爪。
- **主臂（leader / teleop）**：你用手握住的"遥控器"，用来给从臂"做示范"。

## 什么是 LeRobot 和 GR00T？

- **LeRobot**：Hugging Face 开源的机器人库。校准、遥操作、数据采集、策略评估，全都用它提供的统一命令。
- **GR00T**：NVIDIA 的**视觉-语言-动作（VLA）**模型。你给它「看画面 + 一句指令（比如"把试管放进黄色试管架"）」，它输出一连串关节动作，驱动机械臂。

```
输入：  相机画面（2 路） + "Pick up the vial and place it in the rack"
输出：  一连串关节位置动作（让机械臂把试管放进架子）
```

:::{figure} images/gr00t-architecture.png
:alt: GR00T 架构
:width: 80%

GR00T 模型架构：视觉编码器 + 语言编码器 → 跨模态融合 → 动作解码器。
:::

:::{tip}
你屏幕上会拿到一张**工位信息表**（教师下发），上面写着你这个工位的：服务器地址、浏览器网址、分配给串口/相机的参考值、你的前端壳端口等。后面的命令里凡是有「占位符」的地方，都按这张表改成你自己的值。
:::

## 关键要点

- 任务：**抓试管 → 放入黄色试管架**，靠两台 2D 相机完成。
- 仿真负责「快速、安全、多样化」地试错；真实机器人负责最终验证。
- **sim-to-real 鸿沟** = 感知 + 执行 + 物理 + 建模 四类误差的叠加。
- 你负责**操作和部署**，服务器负责**算力**。显卡的重活都不在你的笔记本上。
