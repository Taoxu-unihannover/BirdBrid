# 排错与安全

本章是"急救手册"。遇到问题先来这里查，再动手。

## 排错总原则

1. **看日志，不凭旧结论**：这次报错要以本次日志为准，别拿上次成功的结果套用。
2. **先确认设备身份**：串口名、相机索引、校准 ID 是不是当前这台设备的。
3. **一次只改一处**：别同时改好几个东西，否则不知道是哪个起了作用。
4. **搞不定就断电重启**：很多临时问题断个电重开就好了。

## 常见故障速查表

| 症状 | 先检查什么 | 处理 |
|---|---|---|
| 所有电机都找不到（Missing motor IDs） | 是否接了电源、电源 LED 是否亮 | 接电源、确认 LED 亮，重新运行 |
| 单个电机找不到 | 该电机线缆是否松动、需否重启 | 断电重启；检查菊花链连接 |
| `Torque_Enable` 写入失败 | 电源、USB、电机 ID | 断电重启，检查对应电机线缆 |
| 访问 `/dev/ttyACM*` 权限拒绝 | 当前用户是否在 dialout 组 | `sudo chmod 666 /dev/ttyACM*` 或加组 |
| 串口名变了 / 找不到端口 | 是否重新插拔了 USB | 跑 `lerobot-find-port` 重新确认 |
| 相机画面暗/全黑 | 镜头盖、供电、连接 | 取下镜头盖，确认相机被识别 |
| 相机画面不对（像在瞎抓） | wrist/front 是否插反、索引是否变 | 重跑 `lerobot-find-cameras opencv` |
| 校准不匹配警告 | 是否拿错校准文件 / ID 混淆 | 确认身份，必要时重校，不自动覆写 |
| 抓取总偏同一偏移 | 校准误差、相机位置变化 | 重新校准；核对相机位置和场景 |
| 网页打不开 | 是否把信令端口当网页 | 浏览器要用网页地址（HTTP 端口） |

## 串口与权限

串口名（`/dev/ttyACM0` 等）**不是设备的永久身份**，插拔后会变。判断"哪条线是哪台臂"要用 `lerobot-find-port`（拔一条线再回车）。

访问被拒时：

```bash
# 临时授权（重新插拔后要重跑）
sudo chmod 666 /dev/ttyACM0 /dev/ttyACM1

# 永久方案：加入 dialout 组（相机可再加 video 组），然后注销重登
sudo usermod -a -G dialout "$USER"
sudo usermod -a -G video "$USER"
```

## 电源与电机

:::{important}
USB 只负责通信，**电机要单独电源才有扭矩**。"所有电机缺失"基本都是没接电源。
:::

- 主臂 5V、从臂 12V，**不要混接**。
- 某个电机"随机失联"常见，断电重启一般能恢复。
- 电机是菊花链连接，某处松动会影响后面的电机，检查连接顺序。

## 相机

- **索引会变**：每次拔插相机后都要重跑 `lerobot-find-cameras opencv`。
- **别插反**：wrist（腕部）和 front（外部）搞反，策略必失败。
- 画面暗：先检查镜头盖、供电、对焦。

## 校准

- 腕旋转轴务必**转满行程、摆正中位**，否则编码器上溢/下溢。
- 找的是**机械端点**，不是线缆卡住的位置。线缆卡住会记录出错误的最小/最大值，导致校准失败。
- 校准文件与机器人/ID 一一对应，**别把别人的校准复制过来用**。

## 推理、隧道与端口

| 症状 | 处理 |
|---|---|
| 前端壳起来却没动作返回 | 检查后端引擎地址对不对、是否在跑 |
| `ss -lnt` 看不到你的端口 | 确认前端壳进程没退出，端口没被占 |
| 隧道断了（仿真收不到主臂动作） | 按「仿真 → 隧道 → 采集」顺序重启 |
| 端口被占用 | `ss -lntp` 找到占用进程，别乱 kill，先核对 PID |

## 安全与优雅停止

:::{warning}
**最重要的安全习惯：先停机器人，再停服务；必要时直接拔电源。**
:::

- 停遥操作/评估：先在对应的 client 终端按 **Ctrl+C**。
- 停仿真链路：按「仿真 → 隧道 → 采集」顺序停。
- **后台进程要优雅地停**：如果你用 `nohup ... &` 或后台方式跑了读串口的脚本，直接按 Ctrl+C 或发 INT 信号可能**不会**让它停下，也就**不会释放电机扭矩**。正确做法是找到进程 PID，用 `kill -TERM <pid>` 结束，让脚本有机会释放扭矩、优雅退出：

```bash
# 找到进程
ps aux | grep leader_server
# 用 TERM 优雅停止（不要用 -9 硬杀，除非进程确实无响应）
kill -TERM <pid>
```

:::{tip}
需要可靠释放扭矩的脚本，应当注册 SIGTERM 处理来做清理。课程提供的脚本默认这么做了，所以"用 TERM 停、不要直接拔脚本的命"是关键。
:::

## 保存与恢复

- 校准结果、镜像/环境快照是"能恢复的资产"，建议按教师下发的清单保存。
- 镜像标签是本机 Docker 里的"浮动标签"，不代表已导出离线文件；如果要异机保存，需要另外 `docker image save`。
- 换一台机械臂时，**必须换成那台臂自己的校准文件**，不能沿用旧臂的。

## 求助顺序

1. 查本页对应条目
2. 给机器人**断电重启**（解决很多临时问题）
3. 视觉异常先**重新检测相机**
4. 还是不行，**重跑诊断步骤**，或找教师
