## GR00T 是怎么被"服务化"的？

GR00T 模型本身只是一堆权重，它不会自己"接客"。我们用一个**策略服务器**把它包起来：

```
调用方（client） ──发来「相机画面 + 一句指令」──▶ 策略服务器（server，加载模型）
调用方（client） ◀──回「一连串关节动作」────────── 策略服务器
```

- **server**：加载模型，等待请求，算完动作返回。
- **client**：把观测打包发过去，收动作去执行。仿真里是模拟器，真机里就是机器人的评估脚本。

你后面做的「真机评估」（第 7 章），本质就是让评估脚本当 client，去**调用**推理服务。

## 为什么 8 个人共用一个模型会卡，又怎么解决？

### 问题：串行排队

最朴素的做法是"来一个算一个"（串行）。一次推理约 51 毫秒，8 个工位同时来请求，就得**排成一条队**，后面的人干等：

| 方式 | 8 路并发时最慢的等待（p95） |
|---|---|
| 串行（来一个算一个） | **约 436 毫秒** |

### 解法：批处理（一次算一堆）

GPU 擅长"一次算一大块"。我们把很短时间窗口内（约 6 毫秒）到达的请求**攒成一个 batch（一批）**，一次前向同时算 8 路，再把结果按工位拆开各自发回：

| 方式 | 8 路并发时最慢的等待（p95） | 吞吐 |
|---|---|---|
| 串行 | 约 436 毫秒 | 约 16 次/秒 |
| **批处理** | **约 154 毫秒** | **约 40 次/秒** |

:::{note}
数据来自本项目在 RTX 5090 上的实测（640×480 双相机、batch 上限 8、6ms 攒批窗口）。批处理把 8 路最慢等待从 436ms 压到 154ms，接近 150ms 的实时线。
:::

## 两层架构：后端引擎 + 工位前端壳

为了既吃满 GPU，又让每个学员都有"自己的服务"，我们把服务拆成两层：

```
你（client，评估脚本） ──▶ 你的前端壳（服务） ──▶ 后端批处理引擎（真正持模型）
       端口归你              每个工位一个          全组共一个
```

- **后端批处理引擎**（教师部署，全组一份）：真正加载模型、攒批、做批处理。监听 `tcp://0.0.0.0:5554`。
- **工位前端壳**（你部署，每个工位一个）：监听**你自己的端口**，收到你的请求后转发给后端，再把属于你的那份动作转回来。**它不加载模型，所以 8 个壳互不抢显卡。**

:::{tip}
这就像餐厅：后端引擎是"后厨"（只有一个，但要一起做菜更快），前端壳是"你这个窗口的服务员"（各窗口各司其职，把菜端给你）。
:::

## 动手：部署你的前端壳

假设你的工位是 `s03`，分配端口是 `5582`，后端地址是 `tcp://192.168.1.6:5554`：

```bash
python station_server.py s03 5582 tcp://192.168.1.6:5554
```

看到类似输出说明部署成功：

```
[s03] 前端壳已部署：监听 5582，后端 tcp://192.168.1.6:5554
```

字段含义：`s03` 是你的工位号（仅作日志标识）、`5582` 是你对外监听的端口、最后一个是后端引擎地址。

:::{note}
`station_server.py` 需要能 import 到 GR00T 的序列化协议（`MsgSerializer`），所以它通常在**服务器上的推理容器**里运行。你 SSH 到教师提供的环境里，起**你自己端口**的那份即可。具体登录方式和端口以工位信息表为准。
:::

### 验证你的端口在监听

另开一个终端，执行：

```bash
ss -lnt | grep 5582
```

看到 `0.0.0.0:5582` 在 LISTEN，说明你的服务已经"开门迎客"了。

## 怎么"调用"这个服务？

服务的接口很简单：**发观测（相机画面 + 指令），收动作**。你不需要自己写调用代码——第 7 章的真机评估脚本就是现成的 client，它会连到你的端口来"调用"你的服务。

如果你想先做个最小验证，可以确认链路三段都对得上：

```
评估脚本（连 5582）→ 你的前端壳 → 后端引擎（5554）→ 算出动作 → 原路返回
```

## 关键要点

- GR00T 用 **server/client** 结构提供服务：client 发观测，server 回动作。
- **串行会排队**（8 路最慢 436ms），**批处理一次算一批**（降到 154ms、吞吐翻倍）。
- 架构 = **后端批处理引擎（一份，持模型）+ 工位前端壳（每工位一份，转发）**。
- 你部署的「服务」= 工位前端壳：**监听自己的端口、转发请求、返回属于你的动作**。
